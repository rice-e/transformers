## 3. Comment Cleanup Guidelines

### 3.1 HuggingFace Comment Philosophy

**From CLAUDE.md and HuggingFace Practices**:

> **Brief PRs**: Especially for bugfixes - often just 1-2 lines, no need for extensive comments
> **Composition over abstraction**: Prefer explicit, readable code over complex inheritance
> **Self-contained principle**: Each file should contain all necessary implementation details

**Comment Guidelines**:
- ❌ **Avoid**: Obvious comments that restate code
- ❌ **Avoid**: Excessive implementation details that should be in docstrings
- ✅ **Keep**: Non-obvious design decisions
- ✅ **Keep**: Complex algorithm explanations
- ✅ **Keep**: TODO markers for future enhancements
- ✅ **Keep**: License headers
- ✅ **Keep**: Attribution comments ("Copied from...")
