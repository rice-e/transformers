# Stage 6: Extensibility Analysis and Checker Strategy

## 1. Executive Summary

This document analyzes the extensibility of the Safe Generation feature for supporting custom safety checkers (particularly LLM-based implementations) and evaluates the current checker architecture against the feature's broader goal of **harm prevention**, not just toxicity detection.

**Key Finding**: The current implementation provides **excellent architectural extensibility** for custom checkers through the abstract `SafetyChecker` interface, but has **integration and documentation gaps** that prevent users from easily implementing and deploying custom checkers (including LLM-based safety systems).

**Scope**: Analysis of custom checker support, evaluation of `BasicToxicityChecker` limitations, recommendations for harm prevention architecture, and required improvements for production readiness.

**Critical Insight**: While `BasicToxicityChecker` is a good starting point, the feature's true value lies in its extensibility to support **comprehensive harm prevention** through custom checkers addressing diverse safety categories (violence, self-harm, hate speech, PII, misinformation, etc.).

## 2. Background: Current Checker Architecture

### 2.1 What is BasicToxicityChecker?

`BasicToxicityChecker` is the **default reference implementation** of the `SafetyChecker` abstract base class, located in `/src/transformers/generation/safety/checkers.py`.

**Technical Specifications:**
```python
class BasicToxicityChecker(SafetyChecker):
    """
    Toxicity checker using the s-nlp/roberta_toxicity_classifier model.

    Model: RoBERTa-based binary classifier
    Training: Trained on toxic/non-toxic text pairs
    Output: Probability score (0.0-1.0) for toxicity
    Default Threshold: 0.7 (configurable)
    """

    def __init__(
        self,
        model_name: str = "s-nlp/roberta_toxicity_classifier",
        threshold: float = 0.7,
        device: Optional[str] = None,
    ):
        # Loads pre-trained RoBERTa model for sequence classification
        self.model = AutoModelForSequenceClassification.from_pretrained(model_name)
        # Binary classification: [non-toxic, toxic]
```

**What It Does:**
1. **Input**: Text string or list of strings
2. **Processing**:
   - Tokenizes text (max 512 tokens, truncates if longer)
   - Runs through RoBERTa model
   - Applies softmax to get probability scores
   - Extracts toxic class probability (index 1)
3. **Output**: `SafetyResult` with:
   - `is_safe`: True if toxicity_score < threshold
   - `confidence`: Max(toxicity_score, 1 - toxicity_score)
   - `violations`: List containing toxicity violation if unsafe
   - `metadata`: Model info, scores, thresholds

**Supported Categories:**
- Only `["toxicity"]` - intentionally narrow scope

**Limitations:**
- **Single Category**: Only detects toxic language, not violence, self-harm, hate speech, PII, etc.
- **Binary Classification**: Cannot distinguish between different types of harm
- **English-Centric**: Model primarily trained on English toxic content
- **Contextual Blindness**: Cannot understand context or intent
- **Fixed Model**: Hard to swap for domain-specific models

### 2.2 Design Intent: Starting Point, Not End Goal

From the original design documents (`0.safe_generation_design.md`):

> **Primary Goals:**
> - Enable pluggable safety models (toxicity, bias, PII, custom)
> - Support multiple safety actions (block, revise, rerank, annotate)
>
> **Safety Component Architecture:**
> ```
> SafetyChecker (Abstract Base)
> ├── ToxicityChecker (RoBERTa-based) ← BasicToxicityChecker
> ├── BiasChecker (Custom model)
> ├── PIIChecker (Rule + ML hybrid)
> └── CustomSafetyChecker (User-defined)
> ```

**Key Insight**: `BasicToxicityChecker` was designed as the **minimal viable implementation** to validate the architecture, not as a comprehensive harm prevention solution.

## 3. Feature Scope: Harm Prevention, Not Just Toxicity

### 3.1 The Broader Mission

The Safe Generation feature's purpose extends far beyond toxicity detection:

**Harm Prevention Categories** (from design doc section 4):
1. **Toxicity**: Abusive, insulting, or profane language
2. **Violence**: Content promoting or glorifying violence
3. **Self-Harm**: Suicide instructions, self-injury encouragement
4. **Hate Speech**: Targeted attacks based on protected characteristics
5. **Sexual Content**: Inappropriate sexual material (context-dependent)
6. **Child Safety**: Protection of minors from harmful content
7. **Privacy/PII**: Personally identifiable information exposure
8. **Misinformation**: Factually incorrect harmful claims (medical, safety)
9. **Dangerous Activities**: Instructions for illegal or harmful actions
10. **Bias & Fairness**: Stereotypes and discriminatory content

**Current State**: Only category #1 (toxicity) is supported by `BasicToxicityChecker`.

### 3.2 Real-World Harm Scenarios

**Example 1: Self-Harm Detection**
```python
# Current implementation
checker = BasicToxicityChecker()
text = "Here's how to tie a noose step by step..."
result = checker.check_safety(text)
# Result: is_safe=True (not detected as "toxic" language)
# ❌ MISS: Dangerous self-harm content passed through
```

**Example 2: Violence Glorification**
```python
text = "Detailed instructions for making an explosive device..."
result = checker.check_safety(text)
# Result: is_safe=True (technical language, not "toxic")
# ❌ MISS: Dangerous content passed through
```

**Example 3: Bias Detection**
```python
text = "People from [group] are inherently less capable..."
result = checker.check_safety(text)
# Result: Depends on phrasing - may miss subtle bias
# ❌ INCONSISTENT: Bias often uses non-toxic language
```

**Conclusion**: A toxicity-only checker provides **false sense of security** for comprehensive harm prevention.

### 3.3 Why Extensibility is Critical

Different deployments have vastly different safety requirements:

| Use Case | Required Safety Checks | BasicToxicityChecker Adequate? |
|----------|----------------------|-------------------------------|
| Educational chatbot for children | Violence, sexual content, bullying, PII | ❌ No |
| Mental health support bot | Self-harm, suicide, crisis escalation | ❌ No |
| Customer service agent | PII exposure, brand safety, toxicity | ❌ No (PII missing) |
| Medical information assistant | Misinformation, dangerous advice, privacy | ❌ No |
| General conversation | Toxicity, hate speech, basic safety | ⚠️ Partial |
| Creative writing tool | Minimal filtering, context-aware | ✅ Yes (if threshold high) |

**Key Takeaway**: Production deployments **must** support custom checkers for domain-specific harm prevention.

## 4. Extensibility Analysis: LLM-Based Safety Checkers

### 4.1 Why LLM-Based Checkers Matter

**Advantages of LLM Safety Checkers:**
1. **Multi-Category Detection**: Single model can detect violence, self-harm, hate speech, etc.
2. **Context Understanding**: Can interpret intent and context, not just keyword matching
3. **Flexible Definitions**: Prompt-based customization without retraining
4. **Domain Adaptation**: Adjust safety criteria per use case via prompts
5. **Explanation Generation**: Can provide reasoning for safety decisions

**Real-World Adoption:**
- OpenAI Moderation API (GPT-based)
- Anthropic Claude for safety evaluation
- Meta's LLaMA Guard (instruction-tuned for safety)
- Perspective API + LLM hybrid systems

**Market Demand**: Organizations deploying LLMs increasingly use LLM-as-judge patterns for safety.

### 4.2 PR Review Findings: Custom Checker Support

The PR review agent identified the following gaps for custom LLM checker support:

#### ✅ **Strengths: Excellent Architecture**

**Abstract Base Interface** (base.py:215-263):
```python
class SafetyChecker(ABC):
    @abstractmethod
    def check_safety(self, text: Union[str, list[str]], **kwargs) -> SafetyResult:
        """Minimal interface - only method required"""
        pass

    @property
    @abstractmethod
    def supported_categories(self) -> list[str]:
        """Declare what this checker detects"""
        pass
```

**Why This Works Well:**
- ✅ Only 2 required methods - easy to implement
- ✅ Flexible `**kwargs` for custom parameters
- ✅ Supports both single and batch checking
- ✅ Returns structured `SafetyResult` with violations
- ✅ No dependency on specific model types

**Performance Optimizations** (processors.py):
- ✅ SHA-256 caching reduces redundant API calls (90%+ savings)
- ✅ Check intervals configurable (check every N tokens)
- ✅ Sliding window limits tokens sent to LLM APIs
- ✅ Incremental checking avoids re-processing
- ✅ Prefix cache reuses results for similar sequences

**Error Handling**:
- ✅ Fail-safe approach (assumes unsafe on errors)
- ✅ Perfect for unreliable external APIs
- ✅ Logs errors without crashing generation

#### ⚠️ **Gaps: Integration and Documentation**

## 4.3 CRITICAL ARCHITECTURAL ISSUE: BasicToxicityChecker in Core

### PR Review Discovery: Infrastructure vs. Implementation Violation

The PR reviewer identified a **fundamental architectural problem**: `BasicToxicityChecker` is included in core transformers infrastructure, violating the "infrastructure-only" principle.

**Current State (PROBLEMATIC)**:
```
/src/transformers/generation/safety/
├── base.py                    # ✅ Infrastructure (SafetyChecker ABC)
├── processors.py              # ✅ Infrastructure (SafetyLogitsProcessor, etc.)
├── configuration.py           # ✅ Infrastructure (SafetyConfig)
├── checkers.py                # ❌ IMPLEMENTATION (BasicToxicityChecker)
└── __init__.py                # ❌ Exports BasicToxicityChecker from core
```

**Hardcoded Usage in Core**:
1. **`/src/transformers/generation/safety/__init__.py`** (line 21, 39):
   ```python
   from .checkers import BasicToxicityChecker  # ❌ Exported from core
   __all__.extend(["BasicToxicityChecker", ...])  # ❌ Part of public API
   ```

2. **`/src/transformers/pipelines/safe_text_generation.py`** (line 177-187):
   ```python
   from ..generation.safety import BasicToxicityChecker  # ❌ Hardcoded import
   self._safety_checker = BasicToxicityChecker(...)      # ❌ Hardcoded instantiation
   ```

3. **`/src/transformers/generation/utils.py`** (line 1110-1114):
   ```python
   from .safety import BasicToxicityChecker  # ❌ Hardcoded import
   safety_checker = BasicToxicityChecker()   # ❌ Hardcoded instantiation
   ```

### Why This Violates Infrastructure Principles

**The Key Distinction**:
- **Infrastructure**: Abstract classes, protocols, processing pipelines (✅ belongs in core)
- **Implementation**: Specific models, concrete checkers (❌ should NOT be in core)

**Precedent Analysis from Transformers Codebase**:

| Feature | Infrastructure in Core | Implementation in Core | Pattern |
|---------|----------------------|----------------------|---------|
| **Watermarking** | ✅ WatermarkingConfig<br/>✅ WatermarkLogitsProcessor | ❌ No default watermark<br/>❌ No specific models | **Pure infrastructure** |
| **LogitsProcessor** | ✅ Base classes<br/>✅ List handling | ✅ Algorithmic utilities (temperature, top-k) | Infrastructure + utilities |
| **StoppingCriteria** | ✅ Base classes | ✅ Algorithmic utilities (max_length, EOS) | Infrastructure + utilities |
| **Safety (Current)** | ✅ SafetyConfig<br/>✅ SafetyChecker ABC | ❌ BasicToxicityChecker<br/>❌ Specific model (s-nlp/roberta) | **Hybrid (inconsistent)** |

**Critical Difference**: LogitsProcessor includes **algorithmic utilities** (temperature, top-k) that don't load external models. BasicToxicityChecker **loads a specific HuggingFace model** (`s-nlp/roberta_toxicity_classifier`), which is fundamentally different.

### The Watermarking Pattern (Correct Precedent)

**How watermarking works** (`/src/transformers/generation/watermarking.py`):

```python
@dataclass
class WatermarkingConfig(BaseWatermarkingConfig):
    # Config contains parameters, NOT implementation
    greenlist_ratio: float = 0.25
    bias: float = 2.0

    def construct_processor(self, vocab_size: int, device) -> WatermarkLogitsProcessor:
        """User-facing config constructs the processor."""
        return WatermarkLogitsProcessor(
            vocab_size=vocab_size,
            device=device,
            greenlist_ratio=self.greenlist_ratio,
            bias=self.bias,
            # ... other params from config
        )
```

**Key insights**:
- ✅ Config class has `construct_processor()` method
- ✅ No default watermark model included
- ✅ Users must explicitly configure watermarking
- ✅ Processor is infrastructure (algorithm), not implementation (specific model)

```python
@dataclass
class SafetyConfig:
    # Remove model-specific fields
    # toxicity_model: str = "unitary/toxic-bert"  # ❌ DELETE

    # Add user-provided checker
    checker: Optional[SafetyChecker] = None  # ✅ User must provide

    def construct_checker(self) -> SafetyChecker:
        """Construct safety checker from config (user must provide)."""
        if self.checker is None:

                "SafetyConfig requires a checker instance. "
```

### Implementing a Custom LLM-Based Safety Checker

You can implement custom safety checkers to extend beyond toxicity detection:

```python
from transformers.generation.safety import SafetyChecker, SafetyResult, SafetyViolation
import openai

class LLMSafetyChecker(SafetyChecker):
    def __init__(self, api_key: str, categories: list[str] = None):
        self.client = openai.OpenAI(api_key=api_key)
        self.categories = categories or ["violence", "self_harm", "hate_speech", "sexual"]

    def check_safety(self, text, **kwargs):
        prompt = f"""Evaluate if this text contains any of: {', '.join(self.categories)}

Text: {text}

Respond with JSON: {{"is_safe": true/false, "category": "...", "confidence": 0.0-1.0}}"""

        try:
            response = self.client.chat.completions.create(
                model="gpt-4",
                messages=[{"role": "user", "content": prompt}],
                response_format={"type": "json_object"}
            )
            result = json.loads(response.choices[0].message.content)

            violations = []
            if not result["is_safe"]:
                violations.append(SafetyViolation(
                    category=result.get("category", "unknown"),
                    confidence=result["confidence"],
                    severity="high" if result["confidence"] > 0.8 else "medium",
                    description=f"Detected {result['category']} content"
                ))

            return SafetyResult(
                is_safe=result["is_safe"],
                confidence=result["confidence"],
                violations=violations,
                metadata={"model": "gpt-4", "categories_checked": self.categories}
            )
        except Exception as e:
            # Fail-safe: assume unsafe on error
            return SafetyResult(
                is_safe=False,
                confidence=0.0,
                violations=[SafetyViolation("error", 0.0, "high", str(e))],
                metadata={"error": str(e)}
            )

    @property
    def supported_categories(self):
        return self.categories
```

#### Enhancement 2: Checker Registry Pattern

**File**: `/src/transformers/generation/safety/__init__.py`

**Proposed Implementation**:
```python
SAFETY_CHECKER_REGISTRY = {
    "basic_toxicity": BasicToxicityChecker,
    # Users can register custom checkers
}

def register_safety_checker(name: str, checker_class: type):
    """Register a custom safety checker for pipeline use."""
    if not issubclass(checker_class, SafetyChecker):
        raise ValueError(f"{checker_class} must inherit from SafetyChecker")
    SAFETY_CHECKER_REGISTRY[name] = checker_class

def get_safety_checker(name: str, **kwargs):
    """Get registered checker by name."""
    if name not in SAFETY_CHECKER_REGISTRY:
        raise ValueError(f"Unknown safety checker: {name}")
    return SAFETY_CHECKER_REGISTRY[name](**kwargs)
```

## 8. Architectural Best Practices for Custom Checkers

### 8.1 Checker Implementation Checklist

When implementing custom safety checkers, follow these patterns:

**Required Methods**:
```python
class MyCustomChecker(SafetyChecker):
    def check_safety(self, text: Union[str, list[str]], **kwargs) -> SafetyResult:
        """MUST: Implement safety checking logic."""
        if isinstance(text, str):
            return self._check_single(text)
        return [self._check_single(t) for t in text]

    @property
    def supported_categories(self) -> list[str]:
        """MUST: Declare what this checker detects."""
        return ["category1", "category2"]
```

**Error Handling Pattern** (Critical for Production):
```python
def _check_single(self, text: str) -> SafetyResult:
    try:
        # Your safety logic here
        result = self._perform_check(text)
        return result
    except Exception as e:
        logger.error(f"Safety check failed: {e}")
        # CRITICAL: Fail-safe approach - assume unsafe on error
        return SafetyResult(
            is_safe=False,  # Conservative: block on errors
            confidence=0.0,
            violations=[SafetyViolation("error", 0.0, "high", str(e))],
            metadata={"error": str(e), "checker": self.__class__.__name__}
        )
```

**Why Fail-Safe**: If safety checking fails (API timeout, model error, etc.), we **cannot verify content is safe**, so we must assume it's unsafe to maintain safety guarantees.

**Input Validation**:
```python
def _check_single(self, text: str) -> SafetyResult:
    # Handle empty text
    if not text.strip():
        return SafetyResult(
            is_safe=True,
            confidence=1.0,
            violations=[],
            metadata={"reason": "empty_text"}
        )

    # Handle very long text (prevent API/model overload)
    max_length = 10000
    if len(text) > max_length:
        text = text[:max_length]
        logger.warning(f"Truncated text from {len(text)} to {max_length} chars")
```

**Metadata Best Practices**:
```python
return SafetyResult(
    is_safe=is_safe,
    confidence=confidence,
    violations=violations,
    metadata={
        "checker_type": self.__class__.__name__,
        "model": self.model_name if hasattr(self, 'model_name') else None,
        "categories_checked": self.supported_categories,
        "check_duration_ms": (end_time - start_time) * 1000,
        "input_length": len(text),
        # Include any checker-specific data
    }
)
```

**Rate Limiting and Retries**:
```python
def check_safety(self, text: str, **kwargs) -> SafetyResult:
    max_retries = 2
    for attempt in range(max_retries):
        try:
            response = self.llm_client.generate(...)
            return self._parse_llm_response(response)
        except RateLimitError as e:
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # Exponential backoff
                continue
            # Final retry failed - fail safe
            return SafetyResult(is_safe=False, ...)
        except APIError as e:
            # Don't retry on other API errors
            return SafetyResult(is_safe=False, ...)
```

```python
import time

def benchmark_checker(checker: SafetyChecker, texts: list[str], num_runs: int = 100):
```
